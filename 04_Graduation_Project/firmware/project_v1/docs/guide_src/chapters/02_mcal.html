Chapter 2MCAL — the register layer

The Microcontroller Abstraction Layer is the only code that touches registers. Most drivers come from the course base set by Eng. Eslam Hefny. They were kept and fixed in their own style rather than rewritten; TIMER1, TIMER2 and the restyled TWI are new.

2.0 Common ground: registers, bits and interrupts

All register addresses are in lib/MCAL/reg_def.h as volatile pointers in data-space addresses (I/O address + 0x20), with bit-name macros. No module includes <avr/io.h>. Bits are changed with the four macros of lib/Service/Bit_math.h:

SET_BIT(reg,bit) compiles to a single sbi or a read-modify-write. That is safe in the main loop, with one exception that matters here: registers whose flags are cleared by writing a one (ADIF, TWINT) and registers that share one address (UBRRH/UCSRC). Each of these is dealt with in its driver below.

Pitfall found in Phase 0 — ISRs dropped by link-time optimisation The course drivers declared their ISRs as void __vector_N() __attribute__((signal));. Nothing in C calls an ISR by name, so PlatformIO's -flto treated the function as unused and removed it: the vector pointed at __bad_interrupt, which jumps to address 0, and the MCU reset whenever the interrupt fired. Every ISR follows the course pattern: the vector function only calls a callback through a function pointer, after a NULL check, so the upper layer decides what happens without MCAL including any upper header. The callbacks of this project are short: the Timer2 callback counts, and the two USART callbacks move one byte.

2.1 DIO — digital I/O MCALF

Purpose

Pin and port access for every HAL driver that drives or reads a GPIO: KPAD, BUTTON, RELAY, LED, BUZZER, and the PWM pins in DIMMER, SERVO and FAN. One addition was made: DIO_voidDisableJTAG.

Hardware / registers

RegisterAddressMeaning of a 1 bit
DDRA/B/C/D0x3A / 0x37 / 0x34 / 0x31the pin is an output
PORTA/B/C/D0x3B / 0x38 / 0x35 / 0x32output: drive high · input: enable the internal pull-up (≈ 20–50 kΩ)
PINA/B/C/D0x39 / 0x36 / 0x33 / 0x30the level on the pin (read only)
MCUCSR.JTD0x54 bit 7JTAG off, PC2–PC5 become I/O; must be written twice within 4 cycles

Design and API

Every function takes a port ID (DIO_PORTA … DIO_PORTD = 0…3) and a pin ID (0…7), checks the range and switches on the port. The pull-up function writes the PORT bit, which is what the hardware needs for an input.

void DIO_voidSetPinDirection(u8 Port, u8 Pin, u8 Dir);   /* DIO_PIN_OUTPUT / DIO_INPUT */
void DIO_voidSetPinValue    (u8 Port, u8 Pin, u8 Value); /* DIO_PIN_HIGH / DIO_PIN_LOW */
u8   DIO_u8GetPinValue      (u8 Port, u8 Pin);
void DIO_voidSetPortDirection(u8 Port, u8 Dir);  void DIO_voidSetPortValue(u8 Port, u8 Value);
u8   DIO_u8GetPortValue(u8 Port);   void DIO_voidEnablePullUp(u8 Port, u8 Pin);
void DIO_voidTogPin(u8 Port, u8 Pin);   void DIO_voidDisableJTAG();

Example — a safe output

RELAY sets the level first and then the direction: DIO_voidSetPinValue(DIO_PORTB, DIO_PIN_6, LOW), then DIO_voidSetPinDirection(DIO_PORTB, DIO_PIN_6, OUTPUT). If the order were reversed and PORTB.6 still held a 1, the heating element would switch on for a few cycles.

Pitfalls

  • MCUCSR also holds the reset-cause flags and ISC2. The JTAG function keeps ISC2 and writes 0 to the flags (writing 0 has no effect on them).
  • Reading a pin right after changing a nearby output can return the old level: the pin synchroniser needs about 1.5 cycles. KPAD therefore waits 5 µs after driving a column low (§3.5).

Re-implementation checklist

  1. Define DDR/PORT/PIN addresses for the four ports.
  2. Write set-direction, set-value and get-value per pin with a switch on the port.
  3. Pull-up = write 1 to PORT while DDR = 0.
  4. Range-check the arguments.
  5. JTAG disable: compute the MCUCSR value once, then write it twice back-to-back.

2.2 GIE — global interrupt enable MCALE

Two one-line functions: GIE_voidEnableGlobalInterrupt() executes SEI and GIE_voidDisableGlobalInterrupt() executes CLI (SREG bit I). They are used in two places: once in main() before the tick starts, and as short critical sections in SERVICE — SCHED reads the 32-bit tick and does the test-and-clear of a task flag with interrupts off; TERM reads and clears its RX-activity flag the same way. Those sections run only in the main loop, where interrupts are always enabled, so a plain disable/enable pair is correct. A version that saves and restores SREG would only be needed if one were ever called from an ISR.

2.3 ADC — analog-to-digital converter MCALF

Purpose

Ten-bit conversions for the two LM35 sensors (AC-01, HTR-07). The application uses only the blocking (polled) conversion, which takes {{ f(N['ADC_CONV_US'],0) }} µs.

Hardware / registers

BitsValueWhy
ADMUX.REFS1:011internal 2.56 V reference: 2560 mV / 1024 = {{ f(N['ADC_LSB_MV'],1) }} mV per LSB, and the LM35 gives 10 mV/°C, so one LSB = 0.25 °C and the raw value is the temperature × 4
ADMUX.ADLAR0result right-adjusted: read the 16-bit ADC (ADCL first, then ADCH)

Timing (computed)

tconv = 13 ADC clocks / 125 kHz = {{ f(N['ADC_CONV_US'],0) }} µs. The first conversion after ADEN takes 25 clocks = {{ f(N['ADC_FIRST_US'],0) }} µs; that is the very first HEATER sample at boot. Each 100 ms task does two conversions (water, then ambient): 208 µs of busy-waiting.

Example

Water at 55 °C → LM35 output 550 mV → ADC = 550 / 2.5 = 220 = 55 × 4. HEATER compares this directly with (set ± 5) × 4, so no division or floating point is needed.

Pitfalls (fixed in Phase 2)

  • Sync after async hung. After one interrupt-driven conversion, ADIE stayed set, the ISR cleared ADIF, and the polling loop waited for ever. ADC_u16StartConversion now clears ADIE and a stale ADIF first.
  • Wrong comment. The course code said AVCC but selected 2.56 V, which is what the LM35 needs; the comment was corrected.
  • The ISR lacked used, externally_visible (LTO).
  • AREF must stay unconnected (pin_map C-5). Tied to 5 V it would fight the internal reference and every temperature would read wrong.

Re-implementation checklist

  1. Choose the reference from the sensor range (0–255 °C fits 2.56 V).
  2. Prescaler so that the ADC clock is 50–200 kHz.
  3. Per conversion: clear ADIE and ADIF, set MUX, set ADSC.
  4. Poll ADIF, clear it by writing 1, read ADCL then ADCH.
  5. Keep the result integer: value × 2.5 mV.

2.4 TIMER0 — 8-bit PWM for the dimmer MCALF

Purpose

Hardware PWM on OC0 (PB3) for the dimmable lamp (LGT-02). An RC filter (R6 10 kΩ, C1 10 µF) turns the PWM into a 0–5 V level for the lamp driver transistor.

Hardware / registers

BitsValueWhy
TCCR0.CS02:00010clock F_CPU / 8 = 2 MHz (DIMMER_TIMER_PRESCALER = TIMER0_DIV_8)
TCCR0.WGM01:0011fast PWM, TOP = 0xFF
TCCR0.COM01:0010 (or 00)non-inverting: OC0 set at BOTTOM, cleared on compare match. 00 = pin disconnected (used for 0 %)
OCR0p × 255 / 100duty cycle

Formulas (computed)

fPWM = F_CPU / (N × 256) = 16 MHz / (8 × 256) = {{ f(N['T0_FREQ'],1) }} Hz, period {{ f(N['T0_PERIOD_US'],0) }} µs. In fast PWM the pin is high for OCR0 + 1 counts, so the real duty is (OCR0 + 1) / 256. With the RC filter (τ = 100 ms) the ripple at 7.8 kHz is negligible, and a level change settles in about 0.5 s (5τ).

Pitfalls (fixed in Phase 2)

  • Swapped COM bits. The course code set COM01:00 = 11 for "non-inverting", which is the inverting mode, so the lamp was brightest at 0 %. test_base reported it as [FAIL].
  • 100 % wrapped to 0. OCR0 = Duty × 256 / 100 gave 256 for 100 %, which an 8-bit register stores as 0. It is now × 255, computed in 16 bits.
  • 0 % is not OCR0 = 0. In fast PWM, OCR0 = 0 still produces a one-count spike every period. DIMMER disconnects the pin (COM = 00) and drives it low instead.
  • A case label carried the wrong name (TIMER0_CTC_DISCONNECTED for TIMER0_NORMAL; same value 0). The name was corrected.

Re-implementation checklist

  1. Prescaler from the wanted PWM frequency (F_CPU / (N · 256)).
  2. WGM = fast PWM, COM = 10.
  3. OCR = p · TOP / 100 in 16-bit arithmetic.
  4. 0 % → disconnect and drive low; 100 % → OCR = TOP.
  5. Pin = output before enabling COM.

Purpose

Two PWM channels with one period: OC1A (PD5) drives the door servo (DOR-02), OC1B (PD4) the AC fan transistor (AC-03). Both SERVO and FAN call TIMER1_voidInit; a second call writes the same values and changes nothing.

Pitfalls

  • The first pin plan put the dimmer on Timer1 too; one TOP for both would have made the dimmer a 50 Hz PWM, too slow to filter into a steady 0–5 V. The dimmer moved to Timer0 (D-17, conflict C-1).

Re-implementation checklist

  1. Mode 14, prescaler 8.
  2. ICR1 = F_CPU/(8·f) − 1, high byte first.
  3. OCR = pulse_µs × ticks_per_ms / 1000.
  4. COM = 10 on the channels in use; pins as outputs.
  5. Make init idempotent, because two drivers share the timer.

Purpose

Formula (computed)

2.7 USART — 9600 8N1, interrupt driven MCALF

Purpose

The serial link to the remote terminal (RUI-01). The driver stays thin: it configures the hardware, exposes the RX-complete and data-register-empty interrupts through callbacks, and writes one byte without waiting. The ring buffers live one layer up in TERM (D-3).

Hardware / registers

BitsValueWhy
UBRRH : UBRRL0 : {{ N['UBRR'] }}baud divider from F_CPU (USART_cfg.h); UBRRH first
UCSRA.U2X0normal speed is accurate enough (+0.16 %)

Formulas (computed)

UBRR = F_CPU / (16 × baud) − 1 = 16 000 000 / 153 600 − 1 = 103.17 → 103 (integer division). Real baud = F_CPU / (16 × (UBRR + 1)) = {{ f(N['BAUD_REAL'],2) }}, error +{{ f(N['BAUD_ERR_PCT'],2) }} %, far inside the ±2 % an 8N1 link tolerates. U2X would give UBRR = 207 with the same error, so it brings nothing. One byte is 10 bits = {{ f(N['BYTE_MS'],3) }} ms; the link carries at most {{ f(1000/N['BYTE_MS'],0) }} bytes per second in each direction.

Pitfalls (fixed)

  • UBRRH and UCSRC share address 0x40. A read of that address returns UBRRH on a real ATmega32, so SET_BIT(UCSRC, …) read UBRRH, set a bit and wrote it back as UCSRC without URSEL — corrupting the format. The register is now written once with URSEL = 1 (Phase 0). Proteus seems to return UCSRC on that read, so the bug did not show in simulation (specification §4, Proteus notes).
  • Hard-coded baud value. UBRRL = 103 was right only at 16 MHz. It is now computed from F_CPU.
  • Blocking TX/RX. Printing the 408-byte admin menu with USART_voidSend would block the loop for 408 × 1.04 ms ≈ 0.42 s. The interrupt API and TERM's rings remove all waiting.
  • The UDRE vector switches UDRIE off when no callback is set; otherwise the interrupt would fire for ever and lock the CPU.

Re-implementation checklist

  1. UBRR from F_CPU; check the error (< 2 %).
  2. Write UBRRH, UBRRL, then UCSRC once with URSEL.
  3. RX ISR: always read UDR (it clears RXC), then pass the byte on.
  4. TX: enable UDRIE after putting a byte in the ring; in the ISR send one byte or disable UDRIE.
  5. Keep the blocking functions only for test code.

2.8 TWI — the I²C master MCALF

Purpose

The bus to the LCD, the lamps, both display digits and the EEPROM. The driver was restyled to the course conventions and extended with a timeout on every wait, error codes on every function, and an address probe used for 24C08 ACK polling. It stays polled, not interrupt-driven (D-4): every transfer is short and bounded (longest regular one: an EEPROM page, ≈ 1.7 ms).

Timing (computed)

One SCL period is {{ f(N['SCL_PERIOD_US'],0) }} µs; one byte on the wire, including its ACK bit, takes 9 periods = {{ f(N['TWI_BYTE_US'],0) }} µs. A transaction of n bytes (address included) takes about 10 µs + n × 90 µs. Transaction-by-transaction numbers are in §7.3.

Anatomy of the most frequent transaction, one LCD byte.

The timeout counts loop passes, not time. TWI_cfg.h assumes 6 cycles per pass, giving 2666 passes ≈ 1 ms. The compiled loop (in, sbrs, rjmp, sbiw, brne) takes {{ N['TWI_LOOP_CYC'] }} cycles, so the real timeout is 2666 × 8 / 16 MHz = {{ f(N['TWI_TIMEOUT_MS'],2) }} ms (computed from the disassembly of the avr-gcc 7.3.0 build). It is still far longer than a normal byte (90 µs ≈ 180 passes) and inside the 2 ms that test_mcal checks.

Pitfalls

  • A stuck bus hung the loop. The course driver waited for TWINT for ever. With a slave holding SDA low, every loop pass stopped. Each wait now ends after ≈ 1.33 ms, the bus is released (STOP, then TWEN off/on), and TWI_ERR_TIMEOUT goes up the call chain. LCD_BUF, LAMP, SEVEN_SEG and ESTORE each react to it (chapter 3).
  • A STOP does not set TWINT, so TWI_voidSendStopCondition does not wait. The hardware finishes the STOP before it starts the next START.
  • Bus timing depends on the pull-ups: 4.7 kΩ at 100 kHz is right for the short Proteus bus.

Re-implementation checklist

  1. TWBR from F_CPU and the SCL frequency.
  2. One SendCommand(flags) = write TWCR, wait TWINT with a timeout.
  3. Check TWSR after every step and return a code.
  4. Build transmit, receive and write-read on top; always end with STOP.
  5. Add a probe (START + SLA+W + STOP) for presence checks and EEPROM ACK polling.

2.9 EXTI — external interrupts MCALF

INT0 (PD2), INT1 (PD3) and INT2 (PB2) with selectable sense (MCUCR.ISC0x/ISC1x: low level, any change, falling, rising; MCUCSR.ISC2 for INT2) and enable bits in GICR. The application does not use EXTI in v1; PD2 stays reserved for the PIR sensor (ALM-02, not built). test_base and test_mcal exercise it with a push button on PD2.

Fixed in Phase 2: the three ISRs got used, externally_visible; the callback setters EXTI_voidINT0/1/2_callBack are now declared in EXTI.h; and each ISR checks the callback for NULL before calling it. Before the fix, an interrupt with no callback set jumped to address 0.

Also present but unused: lib/MCAL/SPI (course stub; its missing return was fixed in Phase 0). No SPI device is fitted.
