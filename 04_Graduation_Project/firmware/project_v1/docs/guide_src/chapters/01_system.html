Chapter 1System and architecture

What the system must do, how the firmware is cut into layers, and how the four scarce resources of an ATmega32 — 32 I/O pins, three timers, 32 KB of flash and 2 KB of RAM — were shared out.

1.2 Layers and the rules between them

Module call graph as built: one arrow = one module calls another (from the #includes and calls of every .c). Dashed: the two approved SERVICE → MCAL shortcuts. No arrow goes upwards, and no APP module reaches MCAL.
Layer rules (specification §5, architecture §1.1)
  1. A layer only calls the layer directly below it; APP may also use SERVICE.
  2. SCHED → TIMER2 and TERM → USART skip the HAL because no chip sits in between (D-2).
  3. SERVICE utilities (RINGBUF, MAVG, FMT, the type headers) touch no hardware and may be used anywhere.
  4. A HAL module may use a lower HAL module when one chip sits behind another: LCD_BUF → CLCD → PCF8574, LAMP → PCF8574, SEVEN_SEG → PCF8574.
  5. MCAL never includes an upper header. Interrupts reach upper layers only through callbacks (MOD_SetCallBack…).
  6. Inside APP: UI → SEC → ALARM → feature, and UI → feature. Feature modules never call a UI; they post events to EVQ.
  7. APP code never touches a register, a port or a pin number. All pins live in _cfg.h files.

Every module is three files, MOD.c / MOD.h / MOD_cfg.h, in its own folder. Of the 42 modules, 3 course drivers are used unchanged (GIE is used; SPI and SSG are compiled but never called), 9 were fixed or extended, and 30 are new.

1.3 Pin map and the 32-pin budget

Wired directly, the full feature list needs about 41 I/O lines (specification §7). The ATmega32 has 32. Four decisions closed the gap:

  • the LCD went from a 4-bit parallel bus to a PCF8574 I²C expander (6 pins → 0 extra pins);
  • the five lamps sit on a second PCF8574;
  • the two 7-segment digits each got their own PCF8574 (D-20). This also removed the 7447 decoder and its 6 port pins;
  • the EEPROM is an I²C 24C08.

The I²C bus costs two pins (PC0, PC1) for five chips.

ATmega32 DIP-40 pin assignment as built (docs/pin_map.md, the _cfg.h files). The 32 I/O pins by port and bit.
Hardware notes kept from pin_map.md §4 PB5–PB7 are also the ISP pins (C-4): on a real board, add series resistors so programming does not toggle the heater outputs. AREF must stay open, because the ADC uses the internal 2.56 V reference (C-5). The buzzer needs an NPN driver stage on real hardware (C-9). PC2–PC5 are JTAG pins on a real chip, but they are unused since D-20, so DIO_voidDisableJTAG() is not called at boot.

Only the main loop uses the bus; no ISR touches it, so two transactions can never interleave and no bus lock is needed. The PCF8574 is a 100 kHz part, which is why the bus runs at 100 kHz, not 400 kHz.

1.8 Boot order

main() does three things: initialise every module in a fixed order, enable interrupts, and run the super-loop (chapter 6). The order matters:

  1. Outputs to a safe state first. RELAY, LED, BUZZER, FAN, SERVO, DIMMER set the pin level before the pin becomes an output, so neither heater element can switch on during reset (HTR-06).
  2. Communication and the I²C parts: TERM (UART + rings), then LCD_BUF_voidInit, the only long blocking call (CLCD power-up delays), then LAMP, SEVEN_SEG, KPAD, BUTTON, LM35.
  3. Storage: ESTORE_voidInit reads the 208-byte image from the 24C08 (or loads the defaults on a blank chip), then USERDB_voidInit repairs a missing admin, then EVQ_voidInit.
  4. APP modules: ALARM, SEC, LIGHT, DOOR, CLIMATE, HEATER, UILOC, UIREM. None of them posts an event or calls SCHED, so the queue is empty when the loop starts.
  5. Time base last: SCHED_voidInit, GIE_voidEnableGlobalInterrupt, SCHED_voidStart. The tick starts only when everything it will drive is ready.
Boot phases measured in simavr from the I²C trace (EEPROM with valid data). The CLCD init alone is {{ f(N['LCD_INIT_MS'],1) }} ms computed (48 ms of _delay_ms + 2.5 ms of bus time), against 51.0 − 0.4 = 50.6 ms measured. docs/architecture.md §4.3 quotes 46 ms (see the discrepancy list). The scheduler starts {{ f(N['SIM']['boot_first_slot_ms']['warm']-5,1) }} ms after reset, and the first 5 ms task runs at {{ f(N['SIM']['boot_first_slot_ms']['warm'],1) }} ms.

On a blank 24C08 the boot takes the same time: the defaults are built in RAM and the 13 pages are written in the background by the 10 ms task, 20 ms per page. In simavr the page writes start at 84.7 ms and the last one at 324.7 ms, for both the real-chip model (5 ms write cycle) and the Proteus model (no write delay).
