Chapter 6The top-level application

src/APP/main.c is about 100 lines. It initialises everything in the order of §1.8, enables interrupts, and runs a super-loop that serves the scheduler flags. This chapter shows how the pieces of chapters 2–5 work together, and follows three real interactions through every layer, with times taken from the simavr run.

6.1 The super-loop

The 500 ms slot calls HEATER_voidTask500ms() and ALARM_voidTask500ms(); the 1 s slot calls UILOC_voidTask1s() and UIREM_voidTask1s(). There is no dispatch table and no function-pointer list: one explicit if per period keeps the order visible and lets the compiler inline everything (with LTO, all task functions end up inside main).

When no flag is set, the loop simply polls the five flags again. That is the idle time: 93–96 % of the CPU in simavr (§7.4). There is no sleep mode; adding SLEEP with the Timer2 interrupt as the wake-up source would be a small change if power ever mattered.

6.5 Scenario 3 — the third wrong login

Scenario 3 (simavr main run, third wrong pair at 26.9 s).

The 3rd failed SEC_u8Login calls ALARM_voidTrigger() inside the same call: elements and fan off and the buzzer on within {{ f(R['latency']['lockdown']['enter_to_buzzer_ms'],1) }} ms of the Enter (simavr). In the next 5 ms call, UIREM sees ALARM_u8IsActive(), empties its print queue, queues the [ALERT] line, switches the echo off and enters LOCKED; from then on received bytes are read and thrown away. In the next 10 ms call, UILOC shows SYSTEM LOCKED / Reset required and ignores keys. HEATER (LOCKED) ignores its buttons. The 500 ms task toggles the buzzer (simavr: toggles 500 ms apart). Lamps, dimmer and door are untouched. Only the RESET pin ends this.
