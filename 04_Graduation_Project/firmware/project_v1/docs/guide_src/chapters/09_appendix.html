E. Glossary

ACK pollingchecking whether an I²C EEPROM has finished its write cycle by sending its address and seeing whether it acknowledges
CTCClear Timer on Compare match: the timer counts to OCR and restarts at 0
Debounceaccepting a mechanical contact's new level only after it has been stable for several samples
Dirty pagean EEPROM page whose RAM copy differs from the chip and still has to be written
Fast PWMtimer mode in which the output is set at BOTTOM and cleared at the compare match; frequency = clock / (TOP + 1)
Hyperperiodthe least common multiple of all task periods; the schedule repeats after it (here 1000 ms)
Hysteresistwo different thresholds for switching on and off, so that a signal near one threshold does not make the output chatter
Jittervariation in the start time of a periodic task
LTOlink-time optimisation: the compiler optimises across files at link time and removes unused functions
MCAL / HALMicrocontroller / Hardware Abstraction Layer: register drivers / part drivers
Overruna task flag set again before the previous one was served (one period lost)
Quasi-bidirectionala pin with a strong pull-down and a weak pull-up (PCF8574): it can sink current but hardly source it
Ring buffera fixed array used as a FIFO with wrap-around head and tail indexes
Super-loopthe endless while(1) in main() that calls tasks when their flags are set
Write-behinda write that updates a fast copy at once and the slow medium later, in the background
WCETworst-case execution time

F. Interview questions about this project

QuestionShort answer
Why a layered architecture on an 8-bit MCU?Each layer can be tested on its own (one test program per layer), pins live in one place, and a part can be replaced without touching the application — the 7-segment redesign changed one HAL driver and nothing above it.
How do you get an exact 1 ms tick at 16 MHz?Timer2 CTC, prescaler 64 → 250 kHz, OCR2 = 249 → 250 counts = 1.000 ms; a compile-time #error rejects an F_CPU that cannot give an exact millisecond.
What does your ISR do, and why so little?Counts the tick and sets task flags (≈ 16 µs). Short ISRs keep interrupt latency low for the UART and avoid sharing complex state with the main loop.
How are the ISR and the main loop kept consistent?volatile on shared data; multi-byte values and read-modify-write of flag bytes with interrupts off; single-producer/single-consumer ring buffers with 8-bit indexes need no lock.
Why can two tasks never start in the same millisecond?Their first-due ticks are 5, 12, 101, 503 and 1004: different modulo 5, and every period is a multiple of 5 ms.
What is the worst-case loop pass and how did you check it?The 10 ms slot with an EEPROM page write and a lamp toggle: ≈ 2.15 ms computed, 2.05 ms measured in a cycle-accurate simulation; no overruns.
Why does the LCD not block the loop?LCD_BUF keeps a wanted and a shown screen in RAM and sends at most one byte (≈ 0.46 ms) per 5 ms call.
How do you write an EEPROM without a 5 ms delay?RAM image + dirty bits; every 10 ms one step: write one page, or one ACK poll. Highest page first so the magic byte is written last.
How do you send 400 bytes over a 9600-baud UART without blocking?TX ring buffer + UDRE interrupt; the UI prints one line per 5 ms call and only when 64 bytes are free.
Why is the I²C driver polled and not interrupt-driven?Every transfer is short and bounded (≤ 1.7 ms) and only the main loop uses the bus; an interrupt-driven master with a queue would be a much bigger module. Each wait has a timeout so a stuck bus cannot hang the loop.
How did you fit about 41 I/O lines on 32 pins?LCD, lamps and both display digits on PCF8574 expanders and the EEPROM on the same I²C bus: 2 pins for 5 chips.
Why are the lamps active low?A PCF8574 can sink 25 mA but sources only ≈ 0.1 mA, and it powers up with every pin high — which then means all lamps off.
How is the LM35 read without floating point?With the 2.56 V reference one ADC step is 2.5 mV = 0.25 °C, so the raw value is the temperature × 4; thresholds are compared × 4 as well.
Explain the heater control law.A 10-sample moving average at 100 ms; below set − 5 heat, above set + 5 cool, in between keep the state; no decision until 10 samples exist.
Why hysteresis for the AC?A single threshold makes the fan chatter on noise; on above 28 °C and off below 21 °C gives a 7 °C dead band.
What happens on the 3rd wrong login?SEC calls ALARM in the same call: heater and fan forced off, buzzer beeping, UIs locked; only a reset clears it, because the state is not stored.
How are keypad and remote users kept apart?Separate lists in EEPROM; the admin record is checked only for the UART; the keypad is blocked while the admin is logged in unless allowed.
What did LTO break and how did you find it?ISRs declared only with signal were removed as unused; the MCU reset on the first interrupt. Fix: used, externally_visible. Found by the Phase 0 smoke test of the course drivers.
Tell me about a design that failed.The multiplexed 7447 display: digits ghosted in Proteus; a test bench ruled out the code and the pins, and the display moved to one I²C expander per digit, which also freed 6 pins and emptied the tick ISR.
How would you take this to real hardware?Buzzer driver transistor, series resistors on the ISP pins, check the I²C rise times, enable a watchdog, keep AREF open, verify the EEPROM busy path with a real chip.

H. Regenerating this guide

The guide is generated, so a firmware change can be followed by a rebuild. Sources: firmware/project_v1/docs/guide_src/.

pip install matplotlib schemdraw playwright pypdf     # + graphviz (dot) and a Chromium for Playwright
cd firmware/project_v1/docs/guide_src
python build.py            # figures + PDF  ->  out/Technical_Guide.pdf
python build.py --no-figs  # PDF only

# timing cross-check (Linux): build simavr 1.6 with sim/simavr_v1.6_twi_adc.patch, then
#   avr-gcc ... -flto -o app.elf (flags in sim/README.md) ; ./harness app.elf sim/main.txt main
#   python sim/analyze.py      ->  data/results.json  (read by gnum.py)
  • gnum.py reads F_CPU from platformio.ini and the constants from the _cfg.h files.
  • Code excerpts are pulled from the sources by function name or line range; the build stops if one exceeds 15 lines.
  • Figures are regenerated from the code tables and the simavr data.
