Chapter 4SERVICE — time, text, storage and events

The SERVICE layer holds everything that is neither hardware nor product behaviour. System services — SCHED, TERM, ESTORE, USERDB, EVQ — own a resource and its rules. Utilities — RINGBUF, MAVG, FMT, flash_str.h — are pure code and may be used from any layer. This is also where the ISR world meets the main loop, so each section states exactly what is shared and how it is protected.

4.1 SCHED — time base and task flags SERVICEN

Purpose

A cooperative time-triggered scheduler: the 1 ms Timer2 interrupt sets one flag per period (5, 10, 100, 500, 1000 ms) and the super-loop runs a task when its flag is set. It replaces every _delay_ms of the course code with a structure in which no task ever waits.

Data structure

static volatile u32 Global_u32Tick;          /* ms since SCHED_voidInit          ISR writes , main reads (atomically) */
static volatile u8  Global_u8Flags;          /* bit n = task n due                ISR sets   , main tests-and-clears   */
static volatile u16 Global_u16Overruns;      /* flag set again before served      ISR writes , main reads (atomically) */
static u16 Global_u16DownCount[5];           /* ISR only (loaded before the interrupt is enabled)                    */
static const __flash u16 SCHED_PERIOD_ARR[5] = {5,10,100,500,1000};

Algorithm

Each counter starts at period + offset with offsets 0, 2, 1, 3, 4 ms (SCHED_cfg.h), so the tasks are first due on ticks {{ N['FIRST_DUE']['5MS'] }}, {{ N['FIRST_DUE']['10MS'] }}, {{ N['FIRST_DUE']['100MS'] }}, {{ N['FIRST_DUE']['500MS'] }}, {{ N['FIRST_DUE']['1S'] }} and then every period. Modulo 5 these phases are 0, 2, 1, 3, 4 — all different. Since every period is a multiple of 5 ms, two flags are therefore never set on the same tick, and a long task delays the next one by at most the time it overruns its own millisecond (chapter 7).

Flags set by the tick ISR around t = 1 s.

ISR / main-loop sharing

  • The test-and-clear of a flag in SCHED_u8IsTaskDue runs with interrupts off. The ISR sets other bits in the same byte; a read-modify-write that the ISR interrupts would lose a flag.
  • The 32-bit tick and the 16-bit overrun count are copied with interrupts off: the AVR reads one byte at a time, and a tick between two byte reads gives a torn value (for example 0x00FF → 0x0100 read as 0x01FF).
  • The down-counters belong to the ISR alone; the main loop never touches them after SCHED_voidInit, so they need no protection.
  • Timeouts are counted in calls of the owning task (5 s = 50 calls of the 100 ms task), never by comparing 32-bit tick values, so no module needs SCHED_u32GetTickMs in the loop.

Invariants

  • A flag is set at most once per period; if it is still set when the ISR sets it again, Global_u16Overruns counts the lost period. test_service checks 2000/1000/100/20/10 flags in 10 s with 0 overruns; the simavr runs of the application also end with 0 overruns (§7.6).
  • A late task causes jitter, not drift: the counters keep running in the ISR, independent of when the loop serves a flag.

API and cost

void SCHED_voidInit();   /* Timer2 CTC + callback ; interrupt still off ; may be called again to restart at 0 */
void SCHED_voidStart();  /* OCIE2 on */
u8   SCHED_u8IsTaskDue(u8 TaskID);   /* SCHED_TASK_5MS / 10MS / 100MS / 500MS / 1S ; 1 once per period */
u32  SCHED_u32GetTickMs();  u16 SCHED_u16GetOverruns();

RAM 17 bytes. ISR length {{ R['isr_main']['4']['min_cyc'] }}–{{ R['isr_main']['4']['max_cyc'] }} cycles (simavr) = {{ f(R['isr_main']['4']['min_cyc']/16,1) }}–{{ f(R['isr_main']['4']['max_cyc']/16,1) }} µs, i.e. about 1.6 % of the CPU. architecture.md §4.1 estimates "under 10 µs = 1 %"; the measured value is higher (see the discrepancy list).

Re-implementation checklist

  1. Exact 1 ms CTC interrupt.
  2. ISR: tick++, one down-counter per period, set a bit, count overruns.
  3. Distinct start offsets so no two flags share a tick.
  4. Atomic test-and-clear in the main loop.
  5. Count timeouts in task calls.

4.2 RINGBUF — lock-free byte ring SERVICEN

Purpose

A FIFO of bytes between exactly one producer and one consumer, safe between an ISR and the main loop without disabling interrupts. Used three times: TERM RX (ISR → loop), TERM TX (loop → ISR), and EVQ (loop → loop).

Data structure

typedef struct{
    volatile u8 * Buffer ;   /* storage given by the user                         */
    u8   Size ;              /* bytes of storage ; capacity = Size - 1           */
    volatile u8 Head ;       /* next free slot  - written ONLY by the producer   */
    volatile u8 Tail ;       /* next byte to read - written ONLY by the consumer */
}RINGBUF_t;
Head and Tail; one slot always stays empty.

Algorithm and why it is safe

Empty is Head == Tail; full is Head + 1 == Tail (modulo Size). Keeping one slot empty means the two states never look the same, so no shared counter is needed. Each index is written by one side only, and the AVR writes a u8 in a single instruction, so the other side always sees either the old or the new value, never a torn one.

The order inside Put is the whole trick: store the byte first, then publish the new Head. If the ISR consumer interrupted between the two, it would still see the old Head and not read the unfinished slot. volatile on the buffer stops the compiler (with LTO) from reordering or caching these accesses.

Invariants and cost

  • 0 ≤ count ≤ Size − 1; GetCount may be one step stale when read across an interrupt, which only makes the answer conservative.
  • Users size their storage as capacity + 1: TERM RX 33, TX 129, EVQ 33. Size is a u8, so a ring holds at most 254 bytes.
  • No RAM of its own; 5 bytes per RINGBUF_t.

Re-implementation checklist

  1. Head written by the producer only, Tail by the consumer only.
  2. 8-bit indexes (atomic on the AVR).
  3. One empty slot distinguishes full from empty.
  4. Write data, then publish the index.
  5. Mark the buffer and indexes volatile.

4.3 TERM — UART terminal I/O SERVICEN

Purpose

Turns the USART into a terminal for UIREM (RUI-01): interrupt-driven RX and TX through rings, a line editor with echo, masked echo for passwords, and output that never waits.

Data path. Each ring has one ISR side and one main-loop side.

Data structure

static volatile u8 Global_u8RxStorage[33] , Global_u8TxStorage[129] ;   /* TERM_RX/TX_BUFFER_SIZE + 1 */
static RINGBUF_t Global_RxRing , Global_TxRing ;
static volatile u8 Global_u8RxActive ;                                  /* set by the RX ISR , read-and-clear atomically */
static c8 Global_c8Line[17] ; u8 Length , TooLong , LastWasCR , Echo ;   /* line editor : main loop only */

Algorithm

TX: TERM_voidPut… puts bytes in the TX ring and enables UDRIE. The UDRE interrupt then sends one byte per frame until the ring is empty and switches itself off. The byte is in the ring before UDRIE is enabled, so it cannot be missed. A full ring drops the character; callers check TERM_u8TxFree() first (UIREM prints only when ≥ 64 bytes are free).

RX and line editor (TERM_u8GetLine, every 5 ms from UIREM): bytes are taken from the RX ring and edited.

  • Printable 0x20–0x7E are stored and echoed (or * in masked mode).
  • Backspace 0x08 or Delete 0x7F removes the last character and echoes "\b \b".
  • CR, LF and CR LF each end one line: the LF right after a CR is skipped, even when it arrives in a later call.
  • Other control codes are ignored.
  • A line longer than 16 characters keeps its first 16 on screen, ignores the rest, and returns TERM_LINE_TOO_LONG once when its end arrives.

ISR / main-loop sharing

The rings need no locking (§4.2). Global_u8RxActive (used by UIREM's 120 s idle timer) is read and cleared with interrupts off, because the ISR sets it. The line editor belongs to the main loop alone.

Timing (computed)

The 32-byte RX ring holds {{ f(N['RX_FILL_MS'],1) }} ms of continuous input, far more than the 5 ms between two TERM_u8GetLine calls (at most ≈ 5 bytes arrive meanwhile). The 128-byte TX ring drains in {{ f(N['TX_DRAIN_MS'],0) }} ms. The 408-byte admin menu therefore goes out over ≈ 0.42 s, one line per UIREM step, without the loop ever waiting.

API

void TERM_voidInit();  u8 TERM_u8TxFree();
void TERM_voidPutChar(c8); void TERM_voidPutFlash(const __flash c8*); void TERM_voidPutRam(const c8*); void TERM_voidPutNumber(u16); void TERM_voidNewLine();
void TERM_voidSetEcho(u8);              /* TERM_ECHO_OFF / NORMAL / MASKED */
u8   TERM_u8GetLine(c8 *Line);          /* TERM_LINE_NONE / READY / TOO_LONG ; buffer of 17 bytes */
u8   TERM_u8IsLineEmpty();  u8 TERM_u8IsRxActive();

Re-implementation checklist

  1. RX ISR → ring; TX ring → UDRE ISR.
  2. Enable UDRIE after queuing; disable when empty.
  3. Drop on full, never wait.
  4. Line editor with CR/LF/CRLF, backspace, length limit.
  5. Masked echo for passwords.

4.4 EVQ — event queue SERVICEN

Purpose

The one-way link from feature modules to the remote terminal (RUI-02). A feature module must not call a UI (layer rule 6), yet the terminal must report every change made elsewhere. Features post (event, argument) pairs; UIREM prints them as [INFO] lines.

EventIDArgumentPosted byPrinted as
EVQ_LAMP1lamp numberLIGHT[INFO] Lamp 2 is now ON
EVQ_DIMMER2percentLIGHT[INFO] Dimmer is now 30%
EVQ_AC31 / 0CLIMATE[INFO] AC is now ON
EVQ_HEATER_POWER41 / 0HEATER[INFO] Heater is now ON
EVQ_HEATER_ELEMENT50 / 1 / 2HEATER[INFO] Heater: HEATING
EVQ_HEATER_SET6°CHEATER[INFO] Heater set temperature is now 65C
EVQ_LOCAL_SESSION71 login / 0 logoutSEC[INFO] Keypad user logged in
EVQ_STORAGE_FAULT8—ESTORE[WARN] EEPROM not responding…
EVQ_LOCKDOWN9—ALARMnot printed: UIREM prints the alert from ALARM_u8IsActive()

Design

A RINGBUF of 33 bytes holds 16 events of 2 bytes. EVQ_voidPost checks that 2 bytes are free and then stores both, so an event is never stored half. When the queue is full the new event is dropped and the older ones keep their order. Mute: while UIREM executes one of its own commands it mutes the queue, because that change is already answered with [OK]; the queue therefore only ever holds changes made somewhere else. Main-loop context only: no ISR posts events.

Re-implementation checklist

  1. Fixed-size records in a ring.
  2. Check room for the whole record first.
  3. Drop new on full.
  4. Mute switch for self-caused changes.
  5. Consumer drains when idle.

4.5 ESTORE — EEPROM image with write-behind SERVICEN

Purpose

All persistent data — magic/version, heater set temperature, admin and 10 user records — in a 208-byte RAM image that mirrors bytes 0x00–0xCF of the 24C08 (EEP-01…03, D-5). Reads never touch the chip; writes go out in the background, one page per 10 ms slot, with ACK polling. No caller ever waits for the EEPROM.

EEPROM map (ESTORE_cfg.h, eeprom_map.md). Every record is exactly one 16-byte page.

Data structure

static u8  Global_u8Image[208] ;   /* = chip bytes 0x00..0xCF                 */
static u16 Global_u16Dirty ;       /* bit n = page n differs from the chip (13 bits) */
static u8  Global_u8State ;        /* IDLE / WRITING / FAULT                   */
static u8  Global_u8Polls , Global_u8Status ; static u16 Global_u16PageWrites ;

Algorithm

Boot (ESTORE_voidInit, before the scheduler): one blocking read of 208 bytes (≈ 19 ms). If the read fails: defaults in RAM, state FAULT, nothing is ever written. If the magic (0xA5) or the version (0x01) is wrong: first boot, so load the defaults and mark all 13 pages dirty.

Write: ESTORE_voidWriteByte compares first; an unchanged byte costs nothing, which spares the 1 000 000-cycle endurance. A changed byte updates the image and sets the page's dirty bit.

Write-behind (ESTORE_voidUpdate, 10 ms task): one step per call.

ESTORE write-behind state machine.

Two details carry the reliability:

  • Highest dirty page first. On first boot, page 0 with the magic byte is written last. If power fails during the first-boot writes, the magic is still missing, so the next boot simply starts again.
  • Dirty bit cleared before the write. If a byte of that page changes during the write cycle, the bit is set again and the page is written once more. A change can never be lost between "sent" and "done".

Timing

One page = one 10 ms slot for the write (1.63 ms on the bus) + one slot for the poll = 20 ms per page. A real 24C08 (≤ 5 ms write cycle) is always ready by the next slot; the Proteus model is ready at once. First boot: 13 pages = 260 ms in the background (simavr: page writes from 84.7 ms to 324.7 ms). After 5 failed polls (50 ms) the chip is declared gone: FAULT, EVQ_STORAGE_FAULT, and the system keeps working from RAM.

API

void ESTORE_voidInit();  void ESTORE_voidUpdate();  void ESTORE_voidLoadDefaults();   /* factory reset */
u8   ESTORE_u8ReadByte(u8 Addr);  void ESTORE_voidReadBlock(u8 Addr, u8 *Data, u8 Len);
void ESTORE_voidWriteByte(u8 Addr, u8 Data);  void ESTORE_voidWriteBlock(u8 Addr, const u8 *Data, u8 Len);
u8   ESTORE_u8IsBusy();     /* 0 in FAULT : nobody waits for a write that will never happen */
u8   ESTORE_u8GetStatus();  /* ESTORE_OK / ESTORE_FIRST_BOOT / ESTORE_FAULT */
u16  ESTORE_u16GetPageWrites();   /* diagnostic for test_service */

Invariants

  • The image is the truth; the chip follows within 20 ms per dirty page.
  • Every record is one page, so a record write is atomic (D-6).
  • Page 0 is written only by first boot and factory reset; the heater set temperature has its own page 1, so saving it can never touch the magic byte.

Re-implementation checklist

  1. Mirror the used area in RAM; read it once at boot.
  2. Magic + version → defaults when invalid.
  3. Write = image + dirty bit, skip unchanged bytes.
  4. Background: write one page, poll once per slot, bounded retries.
  5. Highest page first; clear the dirty bit before writing.

4.6 USERDB — accounts SERVICEN

Purpose

The rules for the admin record and the two user lists (SEC-02, 03, 04, 07, 09), stored in the ESTORE image.

Data structure

A record is 16 bytes, one page: name[8] + password[8], padded with 0x00 and not terminated when 8 characters long. A slot is empty when its first name byte is 0x00 or 0xFF (no separate valid flag, D-6). Remote users are at 0x30–0x7F (5 slots), keypad users at 0x80–0xCF (5 slots), the admin at 0x20. The only RAM is Global_u8WriteAccess.

Algorithm and rules

RuleRemote user / adminKeypad user
Name1–8 printable characters 0x21–0x7E (no space)1–8 digits
Password4–8 printable characters4–8 digits
Uniqueinside the list, and not the admin's nameinside the list

Every comparison covers all 8 positions, treating the C string as 0x00-padded. "bob" therefore never matches "bobby", and an 8-character name, which has no terminator in the image, still compares correctly. Only used slots are searched, so an empty name can never match an empty slot. Add and remove write a whole record through ESTORE_voidWriteBlock — one page write, atomic. Remove fills the record with 0x00, so no old password is left behind.

Write gate (SEC-07, D-12): add, remove and set-admin-password return USERDB_ERR_READ_ONLY unless USERDB_voidSetWriteAccess(1) was called, which SEC does only while the admin is logged in. USERDB_voidInit repairs a missing or unprintable admin name with admin / 1234; this repair is not a user action and bypasses the gate.

API

void USERDB_voidInit();
u8 USERDB_u8CheckAdmin(const c8 *Name, const c8 *Pass);                 /* 1 = match */
u8 USERDB_u8CheckUser (u8 List, const c8 *Name, const c8 *Pass);        /* USERDB_LIST_REMOTE / KEYPAD */
u8 USERDB_u8AddUser   (u8 List, const c8 *Name, const c8 *Pass);        /* OK , ERR_FULL/EXISTS/NOT_FOUND/BAD_NAME/BAD_PASS/READ_ONLY */
u8 USERDB_u8RemoveUser(u8 List, const c8 *Name);
u8 USERDB_u8GetUserName(u8 List, u8 Slot, c8 *Name);   /* 1 = slot used ; buffer of 9 */
u8 USERDB_u8SetAdminPassword(const c8 *Pass);  void USERDB_voidSetWriteAccess(u8 State);

Passwords are stored and compared as plain text (D-13): this is a simulation project, and hashing is a listed improvement.

4.7 MAVG — 10-sample moving average SERVICEN

The averaging behind HTR-08 (water) and the AC decision (ambient). MAVG_t holds the last 10 samples, their running sum, an index and a count: 24 bytes per instance. Adding a sample subtracts the oldest from the sum once the window is full, so each update costs O(1), not 10 additions. The average is rounded to nearest in integer arithmetic: (Sum + Count/2) / Count. The sum of 10 samples of at most 1023 is 10 230, which fits a u16. MAVG_u8IsFull tells the caller when 10 samples exist; HEATER makes no decision before that.

Step response at 100 ms per sample. A step reaches a threshold in the middle of the band after about half the window and its full value after 10 samples = 1 s. This is the "average fill time" of the latency chains in chapter 7.

4.8 FMT — number ↔ text without printf SERVICEN

FMT_u8NumberToText(u16, c8*) writes decimal digits (repeated % 10, then reversed) and returns the length; the buffer needs 6 bytes ("65535" + '\0'). FMT_u8TextToNumber(const c8*, u16*) accepts digits only, rejects an empty string, and checks for overflow before the multiplication (value > 6553, or 6553 with a digit > 5). This avoids printf/sscanf, which cost about 1.5 KB of flash and need far more stack.

4.9 flash_str.h — text in flash

RAM is 2 KB, and the terminal text alone is about 2 KB, so every constant string lives in flash. <avr/pgmspace.h> (and PSTR()) pulls in <avr/io.h>, which redefines the registers of reg_def.h. The project uses GCC's named address space __flash instead:

Each FLASH_STR("…") creates a static array in program memory and yields a const __flash c8 *. Functions that print text take that pointer type (TERM_voidPutFlash, LCD_BUF_voidWriteFlash, CLCD_voidSendFlashString), and the compiler emits lpm instructions to read it.

Lesson kept in UIREM.c A switch whose cases only return a text pointer was turned by the compiler into a pointer table in RAM (it cost about 100 bytes). The cases now print the text themselves (UIREM_u8PutFixedText).
