Front matterHow to read this guide

This guide explains the firmware bottom-up: one hardware block, then the driver for it, then the service that uses the driver, then the application feature, and finally the timing of the whole system. Every number, register value, address and formula is taken from the code in firmware/project_v1 or computed from it.

Who it is for

  • An embedded student who knows C and the basics of the AVR but not this code base: read chapters 1–3 in order, then the subsystem you need in chapter 5.
  • The instructor: chapter 1 (architecture and resource budgets), chapter 6 (the traced scenarios), chapter 7 (timing analysis) and chapter 8 (verification and traceability).
  • The author, months from now: the "re-implementation checklist" at the end of every module and the appendices (register reference, pin table, EEPROM map, UART commands).

Conventions

  • Code excerpts are copied from the source file named above them, with the original line numbers. No excerpt is longer than 15 lines; blank lines are left out.
  • Module names are written as in the code: HEATER, ESTORE. Functions follow the course style MODULE_<type><Name>, for example LAMP_u8SetState.
  • Requirement IDs (SEC-05, HTR-09 …) are those of docs/specification.md §6; in the code they appear as /* REQ-HTR-09 */. Design decisions D-1 … D-20 are in docs/architecture.md §9.
  • Colours follow the architecture diagram: blue = APP, green = SERVICE, orange = HAL, purple = MCAL.
  • Module tags: E course driver used as it is, F course driver fixed or extended, N new module written in this project.

Contents

The system on one page

One ATmega32 runs two course projects as one product: a smart home (remote UART terminal, keypad + LCD, accounts in EEPROM, five lamps, a dimmable lamp, a servo door, temperature-controlled air conditioning, an alarm) and an electric water heater (own panel with Up/Down/ON-OFF buttons, two-digit display, heating and cooling elements, 10-sample averaged control with a ±5 °C band). The heater is one more appliance of the smart home: the terminal and the keypad show and change it as well.

Firmware architecture (docs/images/architecture.svg). Four layers; a layer only calls the one below it. Two approved exceptions: SCHED → TIMER2 and TERM → USART (D-2).

How it runs

The Timer2 ISR only counts and sets task flags. main() polls the flags and runs short, non-blocking state machines. The UART is interrupt-driven through ring buffers; I²C is polled from the main loop only, never from an ISR. EEPROM writes go out one page per 10 ms slot from a RAM image.
